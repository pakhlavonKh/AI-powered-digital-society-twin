### Discrepancy 1 (Mandatory Deep-Dive): Ankara Household Count (`1,987,216`) & Household-Population Estimates vs. Total Resident Population (`5,910,320`)

  - **ADNKS Total Private Households (`households_size_and_types.csv`, Table T06/T08, and `ankara_household_size_2025.csv`):** **`1,987,216`** households (`400,484` one-person + `1,312,420` one-family nuclear + `205,415` extended-family + `68,897` multi-person non-family = `1,987,216`).

- **12-Year Historical Trajectory of the Ankara Resident-vs-Household Population Gap (`2014–2025`):**

  - `2025`: Resident Pop `5,910,320` − (`1,987,216` HH × `2.863618`) `5,690,627` = **`219,693`** (`3.72%`)
- **Root-Cause Analysis (Four Compounding Factors):**
  1. **Definitional Universe Difference (Institutional / Collective Population Exclusion):** Under TÜİK ADNKS methodology, total resident population (`T16`/`T30`) includes both private households (*kurumsal olmayan sivil nüfus / özel hanehalkları*) and **institutional/collective places** (*kurumsal yerler nüfusu*: KYK and private university dormitories, military barracks, prisons/penitentiaries, nursing homes, orphanages, long-term hospitals, and police/gendarmerie academies). Ankara is Türkiye's capital and largest university/military/administrative garrison hub; its ~`219,693` institutional residents (Notice the sharp dip to `171,602` in `2020` when university dormitories were evacuated during COVID-19!) are included in `5,910,320` but excluded by definition from the `1,987,216` private households denominator.
  2. **Right-Censored Open-Ended `10+` Household Size Class:** In the NIP household size distribution (`1, 2, ..., 9, 10+`), the `10+` class has only a known lower bound (`household_size_lower = 10`, `household_size = None`). Summing $\sum_{k=1}^{9} k \cdot H_k + 10 \cdot H_{10+}$ yields only a strict **lower bound** on private household members, which is strictly less than the `5,690,627` private household population because households of size `11, 12, ...` exist in `10+`.
  3. **Different Reference Years & Multi-Year Averaging Across Household Sources:**
     - `2021` Building & Dwelling Survey (`housing_stock_and_dwelling_characteristics.csv`) reports **`1,874,093`** households residing in dwellings (matching `2021` ADNKS `households_total = 1,874,093`, not `2025`).
     - `2023` Socioeconomic Status (`socioeconomic_status_and_human_development.csv`) reports **`1,927,404.67`** total households (`47,418.33` `A+`, `318,358.67` `A`, `384,709.33` `B`, `337,346.67` `C1`, `335,540.33` `C2`, `268,907.00` `D`, `235,124.33` `E`) because TÜİK computes SES over a **3-year rolling administrative average**, which does not equal either `2023` ADNKS (`1,920,584`) or `2025` ADNKS (`1,987,216`).
  4. **Absence of Person-to-Household Micro-Linkage Keys:** No public TÜİK table provides joint `(person_age, person_sex, marital_status) × (household_size, household_type)` headship or membership transition matrices for Ankara.
- **Validation & Modelling Policy:** Never scale `1,987,216` households to `5,910,320` persons, never invent an upper bound for `10+`, and never fabricate `household_id` links on resident records. Keep household weights (`unit = household`, sum = `1,987,216`) and resident weights (`unit = person`, sum = `5,910,320`) in separate scopes, and flag any cross-unit equality check as `not_evaluable` (or `fail` if an unverified claim of reconciliation is made) with the exact `219,693` institutional-population and open-tail explanation.

### 5.3 Proposed Check Status Contract (`pass | fail | not_evaluable`)
To satisfy the Global Rule (*"Every check result uses one of three statuses: `pass | fail | not_evaluable`, with a reason"*), `src/societytwin/validation/` will use a canonical Pydantic model inheriting from `TypedModel`:

```python
from typing import Any, Literal
from societytwin.national.dependencies import TypedModel

CheckStatus = Literal["pass", "fail", "not_evaluable"]

class ValidationCheckResult(TypedModel):
    check_id: str
    category: Literal[
        "evidence_integrity",
        "population_marginal",
        "joint_dependency",
        "structural_constraint",
        "cross_source_reconciliation",
        "behavioral_response",
    ]
    status: CheckStatus
    reason: str
    geography: str | None = None
    reference_year: int | str | None = None
    source_ids: tuple[str, ...] = ()
    expected: dict[str, Any] | float | int | str | None = None
    observed: dict[str, Any] | float | int | str | None = None
    metric_name: str | None = None
    metric_value: float | None = None
    tolerance: float | None = None
    discrepancy_id: str | None = None
```
- When an attribute or joint distribution lacks an empirical Ankara reference (e.g., `labour_status` counts in 2025, fine 5-year `age_group × marital_status` in Ankara, `age_group × education_level` in Ankara, person-to-household linkage, or absent local opt-in files in `data/raw/`), the check returns `status="not_evaluable"` with an explicit `reason` explaining why ground truth does not exist.
- When the Ankara household count (`1,987,216`) vs. resident population (`5,910,320`) relationship is checked, the validator verifies `households_total == 1,987,216` (`pass`), `resident_population == 5,910,320` (`pass`), and reports the `person_vs_household_population_reconciliation` check as `not_evaluable` (linked to `discrepancy_id="D1_ANKARA_HH_VS_RESIDENT_POP_2025"`, documenting the exact `5,690,627` implied private-household population and `219,693` institutional/collective population gap without forcing a match).
